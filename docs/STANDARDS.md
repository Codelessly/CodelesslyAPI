# Flutter mirror standard (prototype, 2026-10-29)

**Canonical source:** pinned Flutter widget catalog, then API node field metadata. Breaking changes are permitted; do not add migrators or legacy decoders. The metadata builder covers all 47 existing node classes, but field coverage and renderer parity remain partial.

## Names and shape

- One node per Flutter widget **class**; expose Flutter's constructor parameter names exactly. A variant enum is appropriate only if Flutter presents variants as one class. Existing `ButtonNode` combining `ElevatedButton`, `TextButton`, `OutlinedButton`, `FilledButton` and `IconButton` and `RowColumnNode` combining `Row` and `Column` are transitional exceptions, **not** precedents.
- Node payload: `type` (Flutter class identifier), `props` (only mirrored Flutter arguments), `children` (child references), `extensions` (Codelessly-only bindings/reactions/variants/interactions), and core identity/layout metadata. Existing wire shapes remain until a coordinated breaking release; do not silently rename serialization fields in this metadata pilot.
- `@FlutterNode(widget, family: ..., nodeType: ..., variant?)` names the class and the canonical serialized wire type. Chart, gauge and signature subclasses share one type each and require `variant`, projected as `chartKind`, `gaugeKind` or `signatureKind` in their schemas and DPP descriptors. `@FlutterProp(name, type, group, control, field?, defaultSource?, required?, bindable?, flutterParam?, note?)` decorates a **real field declaration** (including inherited mixin and nested `properties` fields). The generator validates the field path and declares the existing storage name in JSON Schema. `defaultSource` is the upstream expression, not a claimed evaluated JSON default. When Flutter's parameter name and the wire field path differ, a `drift` finding is emitted: this must be resolved before declaring parity. Set `flutterParam: false` with a required note for Codelessly-only convenience fields: their DPP `flutterParam` and `flutterName` are null, and they are excluded from Flutter constructor validation and naming drift. For example, button `properties.label` is label text rendered as the button's child Text; it is **not** Flutter's `child` widget slot.
- Flutter's `material`, `cupertino`, `widgets` families remain separate. `codelessly` extensions never count toward Flutter coverage.

## Package layout target

`lib/src/{core,nodes/<family>,properties,actions,triggers,variables,data,schema}`. `schema/flutter_prop.dart` owns metadata; `tool/flutter_prop_builder` owns build_runner projections. No migrations directory while breaking changes are authorized. Refactor the old `src/api/nodes` tree in one coordinated change only after consumers can be updated.

## Generated projections

`dart run build_runner build` emits checked-in `.flutter_catalog.json` adjacent to annotated nodes with `jsonSchema` keyed by **existing node wire fields**, DPP descriptors (`nodeType`, `flutterName`, `flutterParam`, `fieldPath`, `group`, `control`, `schemaType`, `defaultSource`, `bindable`, optional `note`), A2UI catalog components, and test-matrix inputs. `dart run tool/flutter_prop_builder/bin/merge.dart ../catalog/flutter_3.47.8.json` validates upstream widget and parameter names against the pinned catalog, then emits merged assets under `lib/src/schema/generated/{codelessly_a2ui_catalog.json,dpp_descriptors.json}`. JSON Schema describes annotated wire fields only, not a complete node payload until every node field is annotated. DPP descriptors are not yet wired editor panels. Test values are candidates, not golden results.

A2UI v0.9.1 catalog uses `$schema`, `$id`, `components` (map from component name to JSON Schema), optionally `functions` and `theme`: [upstream basic catalog](https://github.com/google/A2UI/blob/main/specification/v0_9_1/catalogs/basic/catalog.json). [a2ui_core on pub.dev](https://pub.dev/packages/a2ui_core) is the Dart core package; [GenUI Catalog.definition](https://pub.dev/documentation/genui/latest/genui/Catalog/definition.html) describes `components` keyed by name. Catalog `$id` and `catalogId` are fixed at `https://codelessly.com/a2ui/catalogs/codelessly/v1/catalog.json`, protocol v0.9.1. The merged catalog is parsed by `a2ui_core` in tests. `merge.dart` composes the full official 18-component BASIC vocabulary from `a2ui_core`'s generated `BasicCatalog.v0_9()` document (including its shared definitions, functions and Checkable fields) over annotated Flutter-node metadata; the resulting 64 component schemas are **not** 64 available renderers. `basic_node_mappings.json` lists every BASIC name with a typed Codelessly node type or a null/deferred W3 entry. The GenUI store must advertise a smaller verified supported subset with a correspondingly narrowed `anyComponent` union; generated schema presence does not grant an unsupported node or purchase action. Its full 18-name BASIC vocabulary (including `Checkable`, `TextField.value`, `ChoicePicker`, `Tabs`, `Video`, `AudioPlayer`, `DateTimeInput` and `Modal`) comes from the pinned `a2ui_core` v0.9 BASIC catalog. Flutter-named node schemas remain in the same generated document, with collisions such as `TextField` and `Slider` taking the BASIC wire schema; their Flutter field metadata remains in DPP descriptors. **A schema entry does not authorize a GenUI renderer or paywall purchase:** the bridge advertises only its separately tested subset and rejects unsupported W3 components. The old `catalog/v0.9.json` stream ID is separate and must not be silently relabeled. `action` fields reference `common_types.json#/$defs/Action`; `children` fields reference `ChildList`, and single child fields reference `ComponentId`. Converting A2UI action event objects to Codelessly reactions and child references to SDK node IDs is a separate renderer integration, not accomplished by schema generation.

## Tests required per node in production

JSON round-trip, generated schema validation, SDK light/dark goldens, one parity row per upstream constructor parameter, DPP control interaction, and A2UI renderer contract validation. The generator must refuse invalid annotated field paths and missing Flutter class/parameter names before declaring coverage; the current prototype checks field paths and schema types in the builder and Flutter class/parameter names in the merge command. It does not yet verify type and semantic equivalence. No legacy migration fixture (explicitly superseded by the master plan Decisions). Reject unknown fields after adoption; remove dual decode paths and guards.
