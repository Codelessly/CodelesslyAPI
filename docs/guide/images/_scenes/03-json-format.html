The JSON format: three rules
They let an older app show a layout made by a newer Editor.
Versioned
"schema": 2
Older schemas are upgraded on load. Schema 1 (10.x) is not read.
Total decoding
fromJson never throws
Unknown keys, types and props are kept and written back; a bad value falls back to its default.
Sparse encoding
defaults omitted
JSON stays small and diffs readable. Doubles rounded to 4 decimals.
The price of total decoding: decoding doesn't tell you a document is wrong. Checking is a separate step.
Total decoding, on a messy input
The example from this page: what LayoutDocument.fromJson keeps, defaults and drops.
'schema': 2, 'id': 'L', 'roots': ['c', 'missing'], 'nodes': { 'c': { 'type': 'canvas', 'slots': {'body': 't'}, 'layout': {'width': 390, 'height': 844}, }, 't': { 'type': 'text', 'props': {'text': 'Hi', 'maxLines': 'two', 'futureProp': 1}, 'futureKey': true, }, 'x': {'type': 'hologram', 'props': {'depth': 3}}, 'junk': 'not a node', },
Dropped
The root 'missing', and the entry 'junk'.
Default
maxLines: 'two' is not an int: null.
Kept, written back
futureProp in props.unknown, futureKey in extra.
Unknown type
hologram decodes with spec == null and round-trips.

The publish format
A published project is a publish model and its layouts. A bundle is both in one file.
PublishBundle {"model": ..., "layouts": {...}}
PublishModel
Lists every layout without holding it:
  • entryLayoutId, layoutIDMap
  • layouts: canvases, paths, fonts, lastUpdated
  • fonts, theme, apis
  • variables, breakpoints, appIdentity
PublishLayout
home
A layout document with its own keys: paths, variables, conditions...
PublishLayout
checkout
Also decodes as a LayoutDocument.
A slug serves a bundle; Codelessly.asset reads one. Layout ids home and checkout are examples.
