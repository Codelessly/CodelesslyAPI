A layout's logic is data too
This package defines and decodes it; the SDK runs it.
On a node
bind
"props.text": "Hello, ${data.name}!"
actions
Reactions: a trigger and a chain of actions
behaviors
Motion, transitions, interaction states...
In the layout document, per canvas
variables
{"name": "count", "type": "integer", "value": 3}
conditions
if / else if / else branches that set node properties
scripts
JavaScript the SDK runs in a sandbox
Expressions: ${path} reads a value, ${= formula} computes one. App variables are in PublishModel.variables.
A condition
For a property, the first branch that holds and sets it wins. Conditions win over bindings, which win over values.
{"id": "c1", "branches": [ {"when": {"left": "${count}", "op": "greaterThan", "right": "5"}, "set": [{"node": "badge", "path": "visible", "value": true}]}, {"set": [{"node": "badge", "path": "visible", "value": false}]}]}
if
when: a Comparison or an and/or Junction; set: the node properties it gives values.
else
A branch with no when.
A reaction
A Trigger and the chain of ActionDefs it runs in order. One immutable class per action type.
"actions": [ {"id": "r1", "trigger": {"type": "click"}, "actions": [ {"type": "setVariable", "variable": "count", "op": "add", "value": "1"}, {"type": "if", "condition": {"left": "${count}", "op": "greaterThan", "right": "9"}, "then": [{"type": "navigate", "mode": "replace", "to": "done", "params": {"n": "${count}"}}]}]} ]
Trigger
click
Settings are sparse: debounceMs, key...
Action 1
setVariable
count + 1
Action 2
if → navigate
Nested actions: reaction.allActions walks them.
Every action has enabled, nonBlocking and when. An unknown type decodes as UnknownAction and round-trips.
